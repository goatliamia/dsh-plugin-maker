# 形态推导（自建路径第三步）

> 目标：**向导内部判断**该做成什么形态——结论+理由进简报卡，**不向用户弹形态菜单**。形态是实现手段，用户不该也不需要选。

## 形态对照（向导的判断工具）

| 形态 | 适用需求 | 落地位置 | 归属 |
|---|---|---|---|
| **插件（bundle）** | 需要 Host 能力/工具注册/客户端 UI/槽位 | profile bundle，`dsh plugin add` | 平台原生机制 |
| **skill** | 流程/方法论/向导类（模型按需加载的指令集） | skills 目录（SKILL.md + references/） | 平台原生机制 |
| **工作流** | 多代理编排、批量任务 | workflow 脚本 | 平台原生机制 |
| **脚本** | 一次性/定时自动化（不进 agent 工具集） | 项目 scripts/ 或系统计划任务 | 平台原生机制 |
| **agent 预设** | 给特定会话换人设/工具集 | `~/.dsh/.agent-presets/` | 平台原生机制 |
| **自动化任务（看板任务）** | 定时执行、真实会话跑 | 任务看板 | **project-context-bridge 自持 tasks 五列**（待规划/待办/进行中/已完成/已失败，官方 apiProxy 派发）；cron 调度暂缺（字段保留不执行）——第三方 @linxin666 看板已退役 |

> 归属纪律：下"原生"结论前查运行时包清单（`@deepseek-ai/dsh-*` 才是平台原生）。本机已装的第三方能力可用，但报告里必须如实标注"已装第三方"。

## 推导规则（内部四问，不抛给用户）

1. 要"模型会的东西"（skill/预设/提示词）还是"机器跑的东西"（脚本/看板任务/工作流）？
2. 需要出现在 agent 工具列表里吗？（要 → 插件；不要 → 其他）
3. 需要 UI 吗？（要 → 插件 client 半体/槽位）
4. 一次性还是反复？反复且有明确触发 → 脚本+看板任务 / 系统计划任务。

## 原则

- **最轻形态优先**：能用脚本不用插件，能用 skill 不用预设；形态可以组合（如 skill + 脚本）。
- 生态默认插件是"默认候选"，不是"默认答案"——从需求特征推导，推导完在简报卡里给结论+理由，用户只需确认。
